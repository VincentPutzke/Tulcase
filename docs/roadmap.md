# Roadmap and Ideas

This page captures the direction that makes Tulcase more useful for developer reality, not just more feature-rich on paper.

## Near-Term Improvements

- stronger onboarding and screenshots
- richer release documentation
- more docs around database switching and import/export
- end-to-end tests for key extension workflows
- continued consistency work across webview modules

## High-Value Product Ideas

### 1. Better release support

Tulcase already helps with notes, commands, and records. A stronger release toolkit could connect those pieces more intentionally.

Potential additions:

- release checklist templates
- release-specific command groups
- fast handoff note generation
- packaging and docs shortcuts

### 2. More deliberate dashboarding

A dashboard only makes sense if it reduces navigation overhead.

Good dashboard candidates:

- today focus
- current overdue count
- recent records summary
- pinned commands
- recently used notes

### 3. Smarter note and command linking

Notes, commands, and links are often about the same context. Cross-linking them more directly could improve retrieval.

### 4. More operational memory features

Tulcase is strongest when it remembers things the developer should not have to remember manually.

Possible directions:

- recent command usage
- pinned operational procedures
- note templates for recurring activities
- saved filters by project or area

### 5. Team-friendly export patterns

Tulcase is local-first, but some outputs should still be shareable.

Good export candidates:

- weekly summaries
- release notes drafts
- markdown exports for notes
- command bundles for onboarding

## Product Restraint

Not every idea should be built.

Tulcase gets better when new features:

- reduce repeated friction
- reinforce existing workflows
- avoid bloating the interface
- respect the developer's time and attention

## Rule for Future Work

The best additions are usually the ones that remove an already-repeated annoyance.
