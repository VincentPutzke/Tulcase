# Release Plan v0.7.0

This document lists the steps required to prepare and publish Tulcase v0.7.0 (first public release from the `develop` branch into `main`). Mark steps as done when complete.

## Goals
- Ship `tulcase` extension as v0.7.0
- Ensure user data migration from legacy `arbeitsplatz` paths is safe
- CI green, tests passing, and marketplace package published

## Pre-release checklist

1. Code & Metadata
   - [ ] Verify `package.json` fields (name, displayName, publisher, repository URL)
   - [ ] Confirm `version` is `0.7.0` and bump if necessary
   - [ ] Ensure `CHANGELOG.md` has an entry for `0.7.0` describing notable changes and the migration note for existing DBs

2. Tests & Quality
   - [ ] Run unit tests: `npm test` (Vitest)
   - [ ] Run linter: `npm run lint` and fix warnings
   - [ ] Manual smoke test in VS Code (install from local `vsix`) verifying: sidebar, panel views, tags migration works

3. Build & Packaging
   - [ ] Build webview assets: `npm run compile`
   - [ ] Build extension: `npm run prepackage` (invokes compile)
   - [ ] Create package: `vsce package` (generates `*.vsix`)

4. Release PR & CI
   - [ ] Open a PR from `develop` -> `main` with changelog and migration notes
   - [ ] Ensure CI (tests/build) passes on the PR
   - [ ] Get peer review and approvals

5. Finalize Release
   - [ ] Merge PR into `main`
   - [ ] Tag release: `git tag -a v0.7.0 -m "v0.7.0"` and `git push origin --tags`
   - [ ] Publish to Marketplace (optional): `vsce publish` (requires publisher access and PAT)

6. Post-release
   - [ ] Update website/docs and README with release notes
   - [ ] Announce release via channels (Slack, Twitter, changelog entry)
   - [ ] Monitor user reports and prepare hotfix branch if necessary
